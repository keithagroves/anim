How do you remove a plugin from a running program, without restarting it? In V.S. Code, {cue:top}eighty-seven of the top one hundred extensions run code, and removing one means {cue:restart}restarting the whole extension host. {cue:lost}Every cache and connection is lost.
A new paper splits the problem in two. First, {cue:time}time: when a component leaves, everything it changed must be undone. Then {cue:space}space: components depend on each other, and those dependencies come and go while the program runs.
For time, the answer is a {cue:revertible}revertible effect. Every change a component makes, like {cue:cmd}adding a command or {cue:conn}opening a connection, hands the runtime its {cue:inverse}inverse. The runtime keeps them in a stack. To remove the component, it {cue:unwind}runs the stack backwards, and the program is {cue:clean}back exactly as it was.
For space, the answer is a {cue:reactive}reactive coeffect. A component {cue:needs}declares what it needs, say, a database. It waits, {cue:inactive}inactive, until a provider {cue:provides}shows up, then it {cue:activates}activates. If the database {cue:leaves}goes away, the component deactivates, and its effects are undone too.
Both ideas run through {cue:context}one shared context. Every effect and every dependency passes through it, so {cue:independent}components can come and go without disturbing each other. The authors built this as {cue:cordis}Cordis. It already runs {cue:koishi}Koishi, a chatbot framework with {cue:plugins}over four thousand plugins. {cue:goal}Add anything. Remove anything. No restart.
